# Domain expansion protocol

## Purpose

The registry is broad but not literally “every domain on Earth.” It is an extensible starting taxonomy. A new domain is added only as a versioned pack with explicit gaps and reviewers, never by silently asking Cerebrum to guess the industry.

## Required domain-pack fields

- stable domain ID and version;
- sector group and risk tier;
- workflows and actor roles;
- evidence types and provenance requirements;
- jurisdictions;
- applicable ActionNet mechanisms;
- expert specialties and credential requirements;
- prohibited actions and escalation rules;
- source-grounding status;
- review, adjudication, privacy, and release status.

## Addition sequence

1. Reserve a domain ID and semantic-family range.
2. Collect permissioned primary sources and record hashes, versions, dates, jurisdictions, and licenses.
3. Recruit and verify at least the registered number of independent experts.
4. Compile sources into typed institution and workflow candidates.
5. Generate pivotal, invariance, contextual, near-miss, escalation, approval, and denial pairs.
6. Run deterministic reference engines and structural controls.
7. Route cases for blind review and adjudication.
8. Perform privacy, duplicate, leakage, and protected-set checks.
9. Freeze a new domain-pack version.
10. Create a new Cerebrum development identity, seed set, validation split, and protected evaluation reservation.

## Version rule

New expert or customer data never changes the bytes beneath ActionNet-007 or an already executed Cerebrum campaign. It creates an additive ActionNet result and, if approved, a new Cerebrum development experiment.
