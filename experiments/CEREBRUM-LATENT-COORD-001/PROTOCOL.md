# Protocol

## Lifecycle

```text
protocol shell
  -> separate development-data identity
  -> two candidate seeds frozen
  -> independent protected instrument commitment
  -> label-free state projector and runtime freeze
  -> four conditions predict
  -> prediction hashes freeze
  -> one protected score transaction
  -> immutable disposition
```

## State representation

Every condition receives the same time-gated coordination-state record. The
record explicitly includes communication, action, artifact, mutation, resource,
queue, scheduling, configuration, dependency, and lineage channels. The
message-only condition receives a registered projection that removes all
non-message causal edges without altering case identity or time.

## Required outputs

Each prediction conforms to
`schemas/cerebrum/coordination-hypothesis.schema.json` and contains:

- coordination detection and mode;
- direct-communication presence;
- participating entities and proposed roles;
- common-objective hypothesis with evidence references;
- ordered causal edge path;
- downstream state predictions;
- competing explanations and uncertainty;
- risk band and non-binding governance recommendation.

## Independence and custody

The protected generator and causal oracle cannot import ActionNet generators,
Cerebrum training code, development prompts, or candidate outputs. The
custodian controls seeds, hidden institution identities, labels, case order,
overlap audit, and the single score authorization.

Predictions freeze before labels open. After exposure, cases cannot be used for
training, prompt repair, parser repair, model selection, threshold changes, or
confirmatory reuse.

## Safety

All model outputs remain hypotheses with `binding_authority=false` and
`executed=false`. A recommendation such as `EVALUATE_PAUSE` requests
deterministic policy evaluation; it does not pause an action. Any later Kernel
response requires a separately reviewed rule and exact-request authorization.

## Failure handling

A failed gate produces `LATENT_COORDINATION_NOT_ESTABLISHED`. Repair requires a
new ActionNet data identity, a new Cerebrum development identity, and a future
protected protocol with fresh institutions, cases, prompts, generator, oracle,
and labels.
