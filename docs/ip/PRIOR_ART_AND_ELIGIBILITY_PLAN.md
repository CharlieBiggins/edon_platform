# Prior-art, eligibility, and freedom-to-operate plan

Patentability and freedom to operate are different questions and require
separate analysis by qualified counsel. This document defines a reproducible
search handoff; it does not express a legal opinion.

## Search sequence

1. Freeze the candidate mechanism and its earliest known conception record.
2. Break the mechanism into required technical elements and combinations.
3. Search issued patents, published applications, academic papers, standards,
   products, repositories, manuals, and archived web material.
4. Record search strings, classifications, databases, dates, and reviewers.
5. Map each reference element-by-element rather than relying on title or keyword
   similarity.
6. Separate novelty, obviousness, eligibility, ownership, and
   freedom-to-operate observations.
7. Send the complete record to counsel; do not publish legal conclusions.

## Initial search themes

### Compiler and IR

- policy or governance compiler;
- executable policy intermediate representation;
- conflict-preserving knowledge or rule compilation;
- temporal authorization and workflow semantics;
- policy-as-code, access-control, business-rule, and compliance engines.

### ActionNet

- synthetic trajectory and counterfactual experience generation;
- causal replay and parent/child lineage;
- protected benchmark contamination prevention;
- data eligibility and governed training-release systems;
- active learning with simulation coverage gaps.

### Cerebrum–Kernel

- non-binding AI proposal with deterministic authorization;
- capability token or execution token bound to exact request and state;
- AI agent action firewall, shadow execution, and transactional outbox;
- model-lineage-bound action approval;
- monitored planning and safe replanning under hard constraints.

### Federation

- hierarchical federated control and redacted state projection;
- least-common-ancestor escalation;
- local authorization with global non-binding optimization;
- privacy-preserving inter-organizational coordination.

## Element-mapping record

For every material reference, the private search record should contain:

| Field | Required content |
| --- | --- |
| Reference | Publication/application/product identity |
| Effective date | Date relevant to counsel's analysis |
| Elements found | Exact candidate elements disclosed |
| Elements absent | Candidate elements not located |
| Combination issue | Whether another reference supplies the missing elements |
| Technical distinction | Mechanism-level difference, not branding |
| Source copy/hash | Preserved search evidence |
| Reviewer | Person who performed the mapping |

## Software-eligibility framing

The disclosure should emphasize concrete technical operation:

- typed machine state and constrained transitions;
- deterministic validation and rejection behavior;
- replay resistance and exact-request binding;
- transactional consistency and recovery;
- reduced ambiguity, unsafe execution, or inconsistent distributed state;
- a specific improvement to computer-controlled institutional workflows.

Avoid relying on generic statements such as “use AI,” “apply governance,”
“optimize an institution,” or “perform the process on a computer.”
