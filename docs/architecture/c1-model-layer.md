# C1 learned-model layer

C1 is the architectural name for the learned component inside the Cerebrum
System. It is a role, not a claim that one permanent monolithic model must
perform every task.

C1 may support institutional interpretation, authority and policy reasoning,
causal comparison, uncertainty, prediction, planning, and transfer. Validated
deterministic components remain preferable for state commitment, optimization,
authorization, and execution.

## Compatibility rule

The learned component was historically called “Cerebrum” throughout EDON's
experimental literature. Those experiment IDs, artifacts, metrics, and claims
retain their original terminology. C1 is an additive architectural name and
does not convert a historical model result into a full-system result.

The runtime accepts new `EDON_C1_*` configuration names and preserves the
historical `EDON_CEREBRUM_*` aliases. Both paths enter the same non-binding
proposal adapter.

## Model-version lifecycle

```text
institution-local ActionNet candidate experience
  -> local review, privacy, lineage, safety, and overlap qualification
  -> de-identified rights-bound Global ActionNet promotion
  -> content-bound offline training release
  -> offline C1 training
  -> frozen model/adapter and lineage
  -> protected evaluation
  -> optional internal shadow eligibility
```

No operational outcome triggers an automatic gradient update. Every trained C1
version requires a new identity, training-release hash, artifact hash,
evaluation record, and rollback disposition.

Ordinary successors use `C1-v1`, `C1-v2`, and so on. `C2` is reserved for a
future architectural successor rather than a routine checkpoint.

## New institution rule

“New institution does not require a new model” means no institution-specific
weight update is required for the evaluated claim. It does not prohibit
institution-specific IR, retrieval, tools, constraints, context, memory, or
approved non-gradient adaptation.
